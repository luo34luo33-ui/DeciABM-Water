# Demo 说明

## 经营结余、政策承受能力与限额救灾

新建运行不再把原实验的储蓄参数直接当作整户经营结余。每亩每季正常净结余为100～150元：`100 + 50 × (0.6 × 操作能力/4 + 0.4 × clamp((原储蓄参数−500)/1300, 0, 1))`，乘以实际面积并保留到分。原画像储蓄参数另存为`reference_savings_cny`，初始现金、设备报价和滴灌增量收益不变。此处净结余已扣正常经营成本和0.20元/m³基准水费，不重复加原储蓄，也不重复扣基准水费。这是演示校准假设，不是实测农业收益。

地方局决策输入包含用上一季政策、本季气候预测的经营亏损户比例、负现金户比例、上季平均经营结余。预测亏损户达到25%或负现金户达到10%，或者干旱程度下降时，当季水价上限为上季水价的85%；其余季节最多上涨15%。上级事件的水价下限优先，因此干旱事件仍可将价格提高到0.50元。规则局尝试常规调价后受该上限约束，在线局也必须遵守；这不保证所有农户盈利。

每个干旱季设独立救灾预算：辖区面积×30元/亩，不结转，不占设备补贴预算。在设备尚未运行、且不投资时预计季末现金低于两季正常结余的农户中，申请额为`min(干旱损失×50%, 现金缓冲缺口)`。需求超过预算按比例分配并向下取分。救灾款在银行与农户决策前到账，计入现金一次；已运行设备在本Demo中已避免该项干旱损失，不再重复领取。富裕户不因面积大自动领款。设备补贴仍仅在实际投资时支付，银行资金与救灾款不混用。

农户详情显示经营结余、干旱损失、新增水费和救灾到账；地方局详情显示亏损与负现金户比例、救灾预算支出及水价上限。完整分项保存到每季JSON。救灾不直接清零负现金，也不强制采纳；银行原有偿债覆盖率、年龄/操作能力和逾期约束保留。已保存运行的历史值不变，旧运行继续计算不会自动重算其收入画像；需新建运行比较校准后的表现。

## 首屏、连续运行与全流域田块

用水趋势保留实际用水与红线，加入“同季全部沟灌”参照线，浅黄色背景表示干旱区间并标记供水比例。另列“按正常供水折算的用水”：取第0季该范围全部沟灌用水作为正常供水基准，将各季实际用水乘以`正常基准/当季全部沟灌用水`；保持同季面积和设备状态，只剔除供水减少因素。该折算曲线不是实际取水量，不能用于当季红线考核。现有日志已有所需数据，无需改写或重新模拟即可显示，切换地区、村庄和回放时使用相应范围数据。

访问根地址先显示介绍首屏，点击“开始模拟”进入 `/sandbox.html`。模拟页标题可返回首屏，不重置后端运行；Key仅留在当前页面，重新进入需再次输入。旧根地址上的运行、季节和范围链接自动跳转并保留参数。

运行季数可选1、5、10，表示从当前状态追加对应季数，例如第3季追加5季后到第8季。批次开始后冻结环境草稿、模式及本次Key，顺序调用现有单季接口，每季落盘与刷新。停止按钮只阻止后续季，不中断正在结算的一季。请求失败或状态冲突会停止并重新读取已保存状态；在线认证、余额、访问或连续两次建连失败会返回`call_summary.online_unavailable=true`，当前季结果保留但不再调度下一季。个别无效回答仍按原规则代用，数量仅写入运行记录。关闭页面不再启动后续季，当前季以服务器保存状态为准。

全流域田块视图沿虚构河流两岸按上游至下游排列村庄，通过显示平移与缩放排列独立本地坐标中的既有地块，不改变形状、面积或邻接。单击农户仅更新详情，指标仍为全流域口径；“聚焦此村”切换为局部视图。可按地方局筛选、全屏和平移缩放，放大后显示农户编号。逐季更新与历史回放保持同一布局。

## 使用目标

用户扮演流域管理局，下设地方水利局、村级银行和农户。村庄是空间分组，不额外设置村级 Agent。界面将政策、融资、行为与用水关联起来，用于讨论机制。

模型规模在新建运行时设定：地方局 1～6 个，每个水利局管辖 2～4 个村庄，每村 12～18 户。新建运行默认3局、每局2村，每村12～18户独立随机，种子20261022；旧运行保留原规模。每村平均 30 亩/户、两户初始运行滴灌。田块为合成本地平面坐标，不是经纬度。

## 安装与本机运行

Python 3.12+；已验证 Python 3.13。首次运行 `install.bat`，后续运行 `start_backend.bat`。终端保持开启，浏览器访问 <http://127.0.0.1:8000>。

手动启动：在 demo 文件夹执行 `.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`。

服务只监听本机，一个后端进程只维护一个当前运行。不要增加多个 worker。页面刷新可恢复当前运行；进程重启后重新初始化，旧运行仍可从日志回放，但不从历史快照继续计算。

## 逐季时序

1. 更新环境、激活到期设备，执行上季已公布政策；当季上级事件、预算和承受能力约束可限制执行值，救灾款按既有规则到账。
2. 未承诺农户先按本季实际水价和补贴核算：现金优先，差额自动形成逐户贷款申请。这一步是明确规则，不增加Jev调用。
3. 每村农商行读取申请，统一报价并逐户授信；Jev随后读取真实利率与授信，每户每季只调用一次，决定投资或等待。
4. 结算本季投资、补贴、贷款、经营现金与用水，形成共同的本季结果快照。
5. 地方局在最后读取本季真实采纳、拒贷、经营压力和财政支出，制定下一季水价与补贴方案；配额互助用于本季用水考核复核。所有地方局读取同一快照。
6. 保存本季实际政策和下一季方案、原始响应及完整状态。下一季才执行新方案，不追溯改变本季账目。

同季农户决策采用上一季末邻里快照，避免前一个农户的决定影响后一个农户。已承诺者不再重复询问 Jev，不模拟拆除、转售和设备报废。

## 复用与简化

画像来自原 Level3 空间版种子 20261022 的 48 户，已将必要字段复制至 `backend/sim/data/profiles.json`。空间生成沿用不规则边界、Voronoi 分割与一次中心松弛；共享田界才定义为邻居，角点接触不算邻居。

保留现金、普通季节结余、经营增益、风险、能力、信心、支持和邻里信任，调整为可变户数、多个村庄。源数据中已按田块面积缩放的增量收益，先按原面积还原，再按新田块面积缩放。新局初始现金为原画像现金乘以系数，默认65%（5,200～23,400元），新建运行可调30%～150%；原画像现金差异、正常经营结余与画像均保留。降低系数增加融资需求，银行仍须逐户审批，农户自行决定是否使用授信。农户扮演者保持8,000～36,000元独立家底抽签。

原实验中的“空间校准”主要针对 ERPT。在线农户直接使用 Jev；离线规则采用 ERPT 校准评分作为演示参考，并加入贷款利息。新三层系统没有重新进行经验校准。

## 用水和经济公式

以下 A 为亩，d 为供水减少比例，p 为当季水价；基准价 p₀=0.20 元/m³，滴灌节水比例 s=0.30。

- 正常沟灌用水 Q₀=300A；当季沟灌 Qf=Q₀(1-d)；运行滴灌 Qd=Qf(1-s)。
- 设备价 C=1,200A 元；补贴 S=C×补贴率；农户净投资 I=C-S。
- 所需贷款 P=max(0, I-max(0,现金))。现金为负或拒贷时融资不可行。
- 干旱损失 D=2,500×A/30×d/0.30，保留原版线性损失假设。
- 相对基准的沟灌水费增量 W=Qf×p-Q₀×p₀。
- 滴灌运行增量净收益 G=原画像基准增益+D+sW。基准增益已包含基准节水收益，只有水费节省变化 sW 再加入。
- 未运行季现金结余为普通季节结余-D-W；运行后额外获得 G。承诺当季不获得 G。
- 五个运行季、当前条件保持不变的投资净收益参考：5G-I-3Pr；r 为已获批季利率。该值已扣投资和贷款利息，不重复扣贷款本金。

农户作决定时采用谨慎预期：收益按中心估计的90%评估，谨慎五季净收益为5×0.9G-I-3Pr，并偏好约两季普通结余的现金缓冲。缓冲是偏好，不是额外扣费或必须保留的存款。现金优先规则使贷款户付款后的即时现金通常为零，需结合承诺当季结余、首期本息P×(0.2+r)、谨慎运行结余扣首期本息后的余额评估。普通结余已经扣除日常经营支出，不重复扣费。净收益不正、当季现金为负、偿债不足或拒贷仍支持等待；银行批准不代表农户必须安装。实际收益按G结算，阈值仍为0.5，原始Jev概率不做事后修改。

历史运行与已附示例按原记录回放，不追溯改写。要观察新偏好，请重启后端、刷新网页并新建运行；已承诺设备不自动撤销。

上述干旱机制沿用原 Toymodel：运行滴灌被假定能避免所建模的干旱损失，不表示真实作物产量函数。节水是同面积、同供水下的田间用水减少估算，气候减少的取水量不计为设备节水。

新贷款签约利率固定，安装季开始分五季等额还本，最后一期调整分币余数。利息按剩余本金计提；逾期利息不复利。支付优先利息、再本金，未付本息形成逾期，连续两季逾期标为不良贷款本金。普通经营损失可能形成负现金余额，不自动增加授信。

## 年龄、操作能力与银行评估

运行中的农户画像包括：年龄、设备操作能力、风险厌恶、收益信心、技术支持、邻里信任、面积、现金、普通季节结余、设备报价与基准收益，并跟踪设备、债务和最近两季经历。当前源画像年龄为32、46、52、61岁；能力为0～4档，当前样本实际包含1～4档。年龄是初始化特征，不把每一季当作一年机械增加年龄。

银行收到每位申请人的年龄、操作能力、技术支持和经济字段。在线审批与离线备用共同遵守以下Toymodel假设：

- 能力收益系数为0.6+0.1×操作能力；它乘以农户90%的谨慎预期收益，再加当季沟灌现金结余，得到风险调整后可偿债结余。实际生产结算不因此改变。
- 年龄连续经营余量为0.15×clip((年龄-50)/20,0,1)。这是演示用的温和偿债余量调整，不设置退休或年龄禁贷线。
- 最低覆盖率为1.2+0.3×(1-操作能力/4)+年龄余量。操作能力低时要求更多偿债空间。
- 首个还款季本息为贷款额×(0.2+合同季利率)。风险调整后结余除以该本息，不低于逐户最低覆盖率，且现金非负、无逾期、资金足够，才可批准。

例如32岁、能力4档的最低覆盖率为1.20；61岁、能力4档为1.2825；61岁、能力1档为1.5075。高龄熟练农户仍能在偿债余量充足时获批。上述系数是Toymodel参数，不是实证信贷标准。DeepSeek仍逐户作是否放贷的决定并解释依据；违反上述约束的回答重试，仍无效时明确标注规则代用。

## 政策、银行及配额约束

| 设置 | 默认与边界 |
| --- | --- |
| 地方水价 | 初始0.20，允许0.10～1.00元/m³ |
| 设备补贴 | 初始10%，允许0～80% |
| 补贴预算 | 每季辖区设备总报价的25%×用户预算倍数，不结转 |
| 可承诺补贴上限 | 预算除以未承诺设备总报价，并留出分币舍入空间 |
| 银行资金 | 初始为本村设备总报价40%；回收本息补充资金 |
| 本季新授信资金 | 银行季初可用资金×用户信贷比例 |
| 新贷款季利率 | 初始与正常绿色设备贷参考3%，允许1～12%；不是年利率。离线利率=3%+4%×(1-信贷比例)+4%×逾期率，最高12%；在线银行自行报价并说明依据 |
| 配额基础分配 | 流域总红线按经营面积分配 |
| 地区转出上限 | 预测剩余配额与基础配额20%中的较小者 |

授信审批预留资金，只在农户实际投资时放款。未使用授信本季不再次分配。补贴按实际投资支付，未使用部分季末失效。本季回收的贷款资金从下季起可用于新授信。

配额供给和需求不足时按申报量比例成交，再按稳定编号顺序生成双边记录。互助无价格，不是实体水资源输送；只改变地区考核额度。红线不强制截断实际用水。排名按超线比例较低、安装面积占比较高、补贴支出较低排序；不设置额外排名奖金。

## 模型与离线模式

前端将 Key 放在当前请求的 Authorization 头中，后端不读取原项目 `.env`，不保存 Key。

| Agent | 模型接口 | 输出 |
| --- | --- | --- |
| 农户 | OpenRouter Decisions API，`typesafe/jev-1.14` | 原生 noul 倾向值 |
| 地方水利局 | OpenRouter Chat，`deepseek/deepseek-v4.1-flash` | 水价、补贴、配额意向及中文依据 |
| 村级银行 | 同上，每村每季一次 | 新贷款利率、全部申请人审批及逐户依据 |

同阶段最多4个并发，单请求读取超时45秒、连接超时10秒，失败最多重试一次。身份、余额或访问错误停止该轮后续在线调用。持续网络失败后，该轮后续调用使用规则。输出字段、政策范围、申请人对应及授信资金均做检查。

日志同时保留失败响应、错误和替代结果。混合轮次中每个节点都标注实际来源。在线模式下的银行与水利局“依据”是模型返回的说明文字；Jev 本身不生成解释。弹窗中的 p 与1-p是一轮倾向值，不是实测采纳率或重复抽样结果。

离线规则：

- 农户：logistic(-0.1+0.6×经济分+0.4×邻里分+0.3×能力-0.4×风险-现金缓冲惩罚)。经济分为谨慎五季净收益/20,000、截到[-3,3]；能力与风险归一到0～1；邻里分为已安装比例×(0.25+0.75×信任/4)。投资后现金低于两季普通结余时，现金缓冲惩罚为0.15，否则为0。
- 银行：按风险调整后覆盖率与逐户最低要求的比值排序，无逾期、现金非负、覆盖率达到年龄和操作能力对应要求且资金足够才批准。季利率为4%+4%×(1-信贷比例)+4%×逾期余额/贷款余额，上限12%。
- 地方局：预测超线则水价提高10%、补贴增加5个百分点，受价格和预算上限约束；按照预测缺口或盈余提出配额意向。

## 页面与日志

节点选择、图层、图表、范围和季节记录在 URL 中，不包含 Key。页面加载时默认采用当前已执行环境；尚未执行的草稿设置只留在页面内存。

查看历史季为只读；模型和银行详情显示该季保存的决策。已承诺农户保留最近一次真实决策的季号。模型处理中可查看上一季节点详情，不提前显示未结算的新结果。

日志保存在 `backend/logs/<run_id>/tick-0000.json` 等文件中，每轮包含完整状态、当前轮调用和累计指标。原始调用还附在对应Agent最近一次决策中。使用“导出本次运行”可生成一个含全部快照的 JSON，在另一台电脑导入回放。

# 随机村庄与十季事件

顶部将 Key 设置、环境设置和新建运行分为三个窗口。新建运行用滑条调整地方局、每局村数和每村户数上下限；默认12～18户逐村独立抽取，相同种子可复现。将上下限设为同一个数可固定户数。各村使用不同的随机外轮廓和 Voronoi 田块；全流域视图沿虚构河流两岸从左至右排列，表示上游到下游。该河流仅用于空间叙事，不代表真实地理，也不参与河道汇流或上下游配水计算。

新建运行默认勾选如下10季事件，可取消、修改起止季或新增；单季与连续运行均由后端按绝对季数应用，回放和导出保存完整事件与实际环境：

| 季节 | 事件及影响 |
|---|---|
| 第1季 | 基准环境 |
| 第2～10季 | 节水号召：积极性0.8；离线农户效用增加0.45×积极性，在线Jev读取相同事实，不增加经营收益 |
| 第3～4季 | 干旱：供水减少40%，水价下限0.50元/m³，红线降至正常沟灌65% |
| 第5～7季 | 补贴落地：补贴下限55%（仍受实际预算上限约束），补贴预算至少基准2.5倍 |
| 第7～8季 | 信贷收紧：新授信资金比例最多40% |
| 第9～10季 | 红线收紧：红线最多正常沟灌80% |

事件叠加到用户选择的基础环境，结束后撤销临时约束；已承诺设备、现金、贷款与地方局上一季政策仍然保留，政策不会机械重置。第10季之后不会重复触发事件。当前运行的新事件表要通过“新建运行”设置。Key不受新建运行影响。

主界面不显示规则代用项数；原始决策来源、调用数量和错误仍完整写入既有JSON运行记录。Agent详情仍如实标注结果来源。



## 模型连接错误的处理

Key设置支持显示和隐藏，关闭窗口会恢复掩码，输入值仍仅留在页面内存。模型响应中途断开、读取超时或输出不符合约束时，按原策略重试一次；仍失败仅当前Agent采用规则，其他Agent继续在线调用。认证或余额/权限错误，以及同一Agent连续两次无法建立OpenRouter连接，才停止本轮后续在线请求。运行记录保留错误类型与原始细节，区分建连失败、响应中断和业务校验失败。历史日志中的旧提示按原记录保留。
